# CDOT TDM Calculator — Web App

Single-page web calculator that estimates Vehicle Miles Traveled (VMT)
reduction from Transportation Demand Management strategies applied to user-
selected Traffic Analysis Zones (TAZs) in Colorado.

Vite + React 18 + TypeScript + Esri ArcGIS Maps SDK for JavaScript v5,
consuming a hosted feature layer + web map on `hspartner.maps.arcgis.com`.

---

## Quick start

```bash
cd app
npm install               # one-time
cp .env.example .env      # only if you want to override the default web map
npm run dev               # dev server on http://localhost:5180
```

| Script           | Purpose                                                    |
| ---------------- | ---------------------------------------------------------- |
| `npm run dev`    | Vite dev server with HMR (port **5180**, not 5173).        |
| `npm run build`  | `tsc -b --noEmit` then `vite build` → `dist/`.             |
| `npm run preview`| Serve `dist/` locally to sanity-check the prod bundle.     |
| `npm test`       | Vitest, runs the strategy golden-value suite.              |
| `npm run typecheck` | TypeScript check only.                                  |

Port 5180 was chosen to avoid clashing with two other Vite dev servers the
maintainer was running on 5173/5174. If you change it, update both
`package.json` (`dev` script) and the `mcp__claude-in-chrome` snippets in any
test scripts.

## Architecture decisions worth keeping

### 1. Strategy port lives in pure TS, validated against Python

`src/strategies/` has zero React or ArcGIS dependencies. Each function takes
a single `TazInputs` row plus typed `args` and returns a canonical
`StrategyResult`. The same shapes the Python uses, just iterated per-TAZ
from the JS side. `compute.ts` aggregates across the selected TAZs and
applies CAPCOA subsector caps.

`__fixtures__/golden.json` is generated by `scripts/generate_golden_fixtures.py`
— 30 strategy/parameter combinations × 12 representative TAZs = **360 golden
rows**. The Vitest suite in `strategies.test.ts` re-runs every TS strategy
against the same inputs and asserts numeric equality within 1e-6 / 0.5 mi/day
tolerance. Regenerate the fixture when the Python formulas change:

```bash
cd ..                                 # repo root
.venv/bin/python scripts/generate_golden_fixtures.py
```

### 2. Mode share: ACS where present, area-type defaults otherwise

The TS port mirrors Python's `add_imputed_mode_shares(source="auto")` 1:1
via `util.ts` → `imputedModeShare(taz)`: ACS B08301 columns when the
record is populated, `MODE_SHARE_BY_AREA_TYPE` (constants.ts) when the
Census record is suppressed (small / low-population block groups). Every
TAZ produces a computed result — no UI gating, no "requires ACS" badges.

Rationale: ACS-suppressed TAZs are typically small, rural, and contribute
little to aggregate VMT. The area-type approximation is acceptable
relative to the noise floor of the strategy estimates. Golden-value tests
in `strategies.test.ts` exercise both ACS-present and ACS-suppressed TAZs
and verify the JS port matches Python within 1e-6 / 0.5 mi/day.

### 3. Persistent map across views (no auto-fit, just preservation)

The `MapCanvas` is mounted **once** at the top of `App.tsx` inside a wrapper
that toggles `display: block | none` based on the current view. ArcGIS view,
basemap, pan/zoom, and the selection graphics layer all survive a trip into
Shop / Detail / Cart and back. The map deliberately does **not** auto-fit to
the selection — neither on click nor on view return. The user's last view
extent is the source of truth, and the persistent mount means clicking a
TAZ in the area picker never causes a pan/zoom jump.

### 4. Selection rendering uses a dedicated GraphicsLayer

We initially used `FeatureLayer.featureEffect` (saturate + dim non-selected).
The TAZ layer's base symbology is so faint that the dimmed/highlight
contrast was invisible against the basemap — users saw "selected 26 TAZs"
in the sidebar but only one highlighted on the map.

Fix: keep `featureEffect` off and draw selection geometries explicitly into a
sibling `GraphicsLayer` (`selectionLayerRef`) with a vivid blue fill +
1.5-px outline. Updated reactively whenever `selectedTazIds` changes; layer
sits above the feature layer in z-order. Always-visible, no zoom-dependent
issues.

### 5. Polygon-vertex draw, not rectangle drag

ArcGIS's `SketchViewModel.create("rectangle", { mode: "freehand" })` (drag-
to-draw) fought the default map-pan handler. Switching to
`.create("polygon", { mode: "click" })` was both more robust (no
pan-conflict) and produced a more capable UX — users click each vertex and
double-click to close, so they can grab irregular regions, not just axis-
aligned boxes.

### 6. Esri Search biased and filtered to Colorado

The default World Geocoder source is biased to Colorado via
`searchExtent` (CO bounding box) + `countryCode: "USA"` applied to every
source after Search init. That's a soft bias — to make it strict, the
component also filters `suggest-complete` and `search-complete` events
client-side, dropping any result whose display text doesn't match
`/,\s*(CO|Colorado)\b/`. Trade-off: very small CO towns sharing names with
larger out-of-state cities may not surface from a single-word query
(user can add ", CO" to disambiguate). Anonymous public geocoder is used —
no API key needed for basic nav-and-pan usage.

### 7. Dirty-state navigation guards

App.tsx tracks `isDirty = selection > 0 || basket > 0 || workingValues.size > 0`.
Clicking the header logo/title or the "Calculator" nav link runs
`handleHomeNav()` which calls `window.confirm()` when dirty before resetting
state. A `beforeunload` listener attaches when dirty so the browser's native
prompt fires on tab close / refresh / back-button.

## Data sources

Both items are owned by `reichert_hspartner` on `hspartner.maps.arcgis.com`
and shared **public** so the dev app can read them without auth.

| Item             | ID                                  | Purpose                                              |
| ---------------- | ----------------------------------- | ---------------------------------------------------- |
| TAZ feature layer | `9fbb4bd715dc49f09dfe66425c8aecee` | Enriched per-TAZ table (112 fields × 8,045 polygons) |
| Web map           | `b2647df733014039bfa0c7df40054489` | Wraps the TAZ layer over Light Gray Canvas         |

Both URLs are configurable via `.env`:

```env
VITE_WEBMAP_ITEM_ID=...
VITE_PORTAL_URL=https://hspartner.maps.arcgis.com
VITE_TAZ_LAYER_URL=...                # used by data/queryTaz.ts
```

The enriched layer is produced by `scripts/publish_enriched_taz.py` (repo
root), which runs `prepare_taz()`, writes the joined table to GeoJSON, and
publishes it to AGOL. Use GeoJSON specifically (not the SDK's shapefile path)
because shapefile field names are capped at 10 characters — the
long descriptive columns (`length_weighted_auto_op_cost_pk`,
`acs_drove_alone_share`, etc.) would otherwise be mangled.

To republish after the source CSV/script changes:

```bash
cd ..
uv run python scripts/publish_enriched_taz.py
```

The script will create new items each time (idempotent on title); delete
the old ones in AGOL first or edit the title constant.

## Known issues / follow-ups

- **PDF + CSV export buttons are stubbed.** Wire up either client-side
  (jsPDF + html-to-canvas for PDF, plain blob for CSV) or move report
  generation server-side. The cart already has `AggregatedResults` ready to
  serialise.
- **`geoid` BigInt warning.** The TAZ layer's `geoid` column is a 12-digit
  block-group FIPS published as a numeric (max ≈ 1e12, well within
  `Number.MAX_SAFE_INTEGER ≈ 9e15`). Esri's SDK emits an informational
  warning on every load. Re-publishing with `geoid` cast to string before
  the GeoJSON write would silence it.
- **"Failed to load web map" first-load warning.** The SDK occasionally
  logs this even though the WebMap subsequently loads fine. The
  `MapCanvas` effect's poll-and-retry loop recovers without user action.
  Source unclear; doesn't block functionality.
- **Web map auth scope for production deploy.** Both items are currently
  shared `public`. Decide before launch whether to keep them public, move
  to an unauthenticated CDOT-hosted layer, or gate on SSO. The calculator
  has no other auth surface — switching scopes is just a publish-script
  argument.
- **Stale compiled `.js` shadowing `.tsx`.** Earlier builds with
  `tsc -b` (without `--noEmit`) wrote sibling `.js` files into `src/`
  that vite then served instead of the live `.tsx` source. The build
  script now uses `tsc -b --noEmit`. If you ever see HMR stop reflecting
  edits, check for and delete any `src/**/*.js`.
- **No accessibility audit yet.** Sliders + map are the riskiest surfaces.
  Calcite tokens give us a head-start; per UI-AC-04 in the requirements,
  a third-party audit + VPAT is required pre-release.
